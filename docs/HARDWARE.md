# Hardware Standard — The Quiet Operator (solid-octo-potato)

**Updated:** 2026-08-13  
**Aligned with:** Meta Supreme Apex Genesis hardware classes

Reference classes, not shopping lists. A class is defined by the work it must finish without the operator waiting on it. Parts age out within a year; the obligation does not.

This system has three surfaces with different demands: the **web app** (static-first), the **API / Council** (provider-bound), and **Postgres + vector** (the only component whose sizing is arithmetic).

---

## 1. Web

Next.js / static-first. Nothing here justifies a hardware requirement — the Council runs server-side and the browser renders text and layout.

A five-year-old laptop is a legitimate operator machine. An intelligence system that demands a workstation just to *read its output* has misplaced the work.

## 2. API / Council / Orchestration

Async throughout. The bottleneck is almost never CPU.

| Class | Purpose | Floor |
|---|---|---|
| **Bench** | Single operator, offline / zero-key path, no database | 2 cores / 4 GB |
| **Line** | Team use, Postgres attached, live providers | 4 cores / 8 GB / SSD |
| **Room** | Multi-tenant, concurrent councils, embedding backfill | 8+ cores / 16 GB / NVMe |

**Concurrency is bounded by the provider, not the box.** A council deliberation is multiple model calls; wall-clock is provider latency. Adding cores to make deliberation faster is the wrong purchase. Raise async concurrency and provider rate limits instead.

The zero-key offline path remains the canonical CI target: it can be verified anywhere.

## 3. Postgres + vector / RAG

The only component where sizing is arithmetic rather than judgement.

**Index memory is the number that matters.** An HNSW (or equivalent) index wants to live in RAM; once it spills to disk, recall latency degrades sharply.

Rough sizing at 1536-dimension embeddings:

| Vectors | Raw (float32) | Working set with index | Practical RAM |
|---|---|---|---|
| 100 K | ~0.6 GB | ~1 GB | 4 GB |
| 1 M | ~6 GB | ~9 GB | 16 GB |
| 10 M | ~60 GB | ~90 GB | 128 GB, or shard |

Cross the line where the index no longer fits and the honest options are fewer dimensions, quantisation, or sharding — not a faster disk.

## 4. Storage and retention

- **Database**: point-in-time recovery, retained ≥ 30 days. Decision and audit records are product state; a lost log cannot be regenerated by re-running anything.
- **Embeddings are derived** and may be rebuilt from source documents. Back up the documents; the vectors are a cache with an expensive miss.
- Schemas are versioned in the repository.

## 5. What this standard refuses

- **No GPU.** Inference is a provider’s problem. If a code path needs a local GPU, that path belongs behind an API.
- **No hardware answer to a rate limit.** Provider throttling is not solved by a bigger machine.
- **No SKUs.** A class is a floor to clear, not a part number to match.
